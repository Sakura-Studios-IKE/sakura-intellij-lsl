# Sakura LSL — Changelog

All notable changes to this plugin are documented here. Format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions
follow [Semantic Versioning](https://semver.org/).

The `[Unreleased]` section is what's currently on `main`; the release
pipeline promotes it to a numbered version on tag.

## [Unreleased]

## [1.0.1] — 2026-05-15

### Changed
- Tighten supported IDE range to **2025.3 – 2026.2** (`pluginSinceBuild = 253`,
  `pluginUntilBuild = 262.*`). Six of our API calls
  (`DirectoryProjectGenerator`, `JDOMExternalizerUtil`, friends) are marked
  `@ApiStatus.Internal` in 2024.1 – 2025.2 and were promoted to
  `@Experimental` in 253+, where the JetBrains Marketplace verifier permits
  them. Lower this bound only after replacing those calls with public-API
  equivalents.

### Fixed
- Marketplace verifier rejected v1.0.0 with *"Plugin uses the Internal API"*;
  this release passes verification cleanly.


### Added
- Right-click any `.lsl` / `.lslh` file in the editor or Project view →
  **Run in slemu (current file)** (default shortcut `Ctrl+Alt+L`). No
  need to open the Run Configurations dialog for the common case.
- Rich Run Configuration UI with first-class fields for: volume
  directory, `--http-real` toggle, fixture file, `--trace`, owner UUID
  / name / balance, extra avatars, pre-defined commands (file or
  inline), max events, wall-clock timeout, object name, plus a
  catch-all extra-flags field.
- Sakura LSL **tool window** in the bottom dock with two tabs:
  *Emulator* (live JSON event log + send-command input) and
  *Debugger* (an embedded `lsldb` REPL with quick-action buttons).
- **Parameter info** while typing function arguments — for every one
  of the 540 LSL built-in functions, including the currently-active
  parameter highlighted and a `(Mono only)` tag for Mono-only builtins.
- Rich completion entries: shows the function's parameter types as
  tail-text, the return type as type-text, and `(Mono)` flag where
  relevant.
- New-Project wizard with two templates: **Sakura LSL — Just LSL**
  (scripts/, tests/) and **Sakura LSL — Full Stack** (adds
  backend/ FastAPI, migrations/ Alembic, frontend/ React, plus
  docker-compose for PostgreSQL).
- Changelog wiring: this file is read at build time by the JetBrains
  gradle-changelog-plugin and its `[Unreleased]` section becomes the
  plugin's `<change-notes>` automatically.

### Changed
- `<until-build>` widened to `299.*` so the plugin runs on IDEA 2024.1
  through future 2029.x releases.
- Toolchain bumped to Gradle 9.0, IntelliJ Platform Gradle Plugin
  2.16.0, Kotlin 2.3.0.
- `LslBuiltins` now loads the full LSL standard library from a packaged
  `builtins/lsl-builtins-detailed.txt` (540 functions, 534 constants,
  49 events with full signatures), generated by
  `sakura-lslc --list-builtins-detailed`. Replaces the previous
  60-name teaser list.
- The run configuration now hands slemu the compiled `.lslbc` (not the
  source `.lsl`) and uses the correct `-fno-color` flag.

### Fixed
- Plugin previously crashed any IDE that already had another LSL
  language plugin installed (notably `io.github.riej.lsl`) because the
  bare `LSL` Language id collided. Now uses a vendor-qualified
  `sakura-lsl` id so multiple LSL plugins can coexist.
- `<fileType name="…">` and `LslFileType.getName()` now agree (`Sakura LSL`).
- `LslStatusBarWidget.getClickConsumer()` imported the wrong `Consumer`
  type, breaking the IconPresentation contract.

## [1.0.0] — 2026-05-15

### Added
- Initial release: `.lsl` / `.lslh` file type, hand-rolled lexer +
  syntax highlighter, basic completion, lslc-driven external annotator
  with gcc-style diagnostics, two run-configuration types (slemu and
  lsltest), application-level settings page, status-bar compile light,
  Firestorm hot-reload action, copy-to-clipboard fallback.
