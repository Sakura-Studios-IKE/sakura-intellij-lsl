Sakura LSL

A complete IDE experience for Second Life developers working in Linden Scripting Language (LSL). Authored and maintained by Sakura Studios, IKE.

What you get

  • Syntax-aware editor for .lsl and .lslh files: lexer, highlighter, brace matcher, line/block commenter (Ctrl+/, Ctrl+Shift+/).
  • Completion over the full LSL standard library — 540 functions, 534 constants, 49 events — each entry shows its parameter types and return type as tail-text.
  • Parameter info while typing arguments: the function signature pops up with the active parameter highlighted, including a (Mono only) tag where relevant.
  • Quick documentation on hover or Ctrl+Q: category (function / constant / event), full signature, link to the LSL Wiki entry.
  • Live diagnostics via an external annotator that runs sakura-lslc in the background on every pause-in- typing and surfaces gcc-style errors / warnings / suggestions inline.
  • One-click run: right-click any .lsl file → Run in slemu (current file) (Ctrl+Alt+L). The plugin compiles with sakura-lslc, hands the bytecode to sakura-slemu, and streams JSON events into the Run console.
  • Rich Run Configuration UI with first-class fields for the emulator's options: volume directory, real HTTP vs fixture, owner UUID / name / balance, extra avatars table, pre-defined commands (file or inline), object name, step / wall-time caps.
  • Sidebar tool window with two tabs: an Emulator pane showing the live JSON event log plus a send-command input for player actions (TOUCH_AS, DIALOG_REPLY, …), and a Debugger pane that hosts an embedded sakura-lsldb REPL with quick-action buttons (Step, Continue, Locals, Globals, Snapshot).
  • Project wizards: two new templates appear in File → New → Project:
    • Sakura LSL — Just LSL — a clean scripts/ + tests/ skeleton with a Makefile wired up to compile and test.
    • Sakura LSL — Full Stack — the same plus a Python backend/ (FastAPI + SQLAlchemy + Alembic), a frontend/ (React + Vite), and docker-compose.yml with PostgreSQL.
  • Hot reload to Second Life via Firestorm's external-editor watch directory. Configure the path in settings; saving an .lsl drops a copy where Firestorm picks it up and reloads in-world. A Copy script to clipboard fallback is also provided. (LL does not expose a third-party upload API; a logged-in viewer is required.)
  • Status-bar compile light: green / yellow / red, click to navigate to the first diagnostic.

Requirements

IntelliJ Platform 2024.1 or newer (any IDEA, CLion, PyCharm, WebStorm, … all work). The plugin shells out to the sakura-lslc compiler and sakura-slemu emulator binaries. Install those separately from their GitHub releases or, on Arch Linux, via yay -S sakura-lslc sakura-slemu / sakura-lsldb / sakura-lsltest.

After installation, open Settings → Tools → Sakura LSL and point the plugin at your installed binaries.

The Sakura LSL toolchain

This plugin is the IDE front-end for an open-source toolchain. The other tools install independently:

  • sakura-lslc — pure-C99 offline LSL Mono compiler. gcc-style diagnostics, full preprocessor, portable bytecode.
  • sakura-slemu — headless region emulator. Full LSL event loop, listen / link-message routing, L$ economy, linkset-data persistence, HTTP backend (real curl or JSON fixture), HUD / menu / dialog / chat simulation.
  • sakura-lsldb — gdb-style CLI debugger. Source-line breakpoints, single-step, print, catchpoints.
  • sakura-lsltest — pytest-style test framework. Compile-only and full-scene scenarios with player actions.
